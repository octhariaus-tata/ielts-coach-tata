## Ordinary answer-turn procedure

1. Retain verified packet, reference, lesson ID, CLI contract and next step in active context. Restore only the missing state after restart, ambiguity or changed evidence. No repeated prepare/pull, help, broad search, scorecard or delegation between answers.
2. Run lesson checkpoint with --defer-sync; use its successful persisted readback before assessment. Preserve exact first response and partial/complete/paused status. Do not add a duplicate read merely to repeat a verified operation.
3. Think carefully about meaning and language: fact polarity, pronouns, auxiliary, units, spelling, acceptable alternatives and actual scope. Resolve ambiguity with evidence; uncertainty takes priority over speed. Official evidence rules and withheld keys still apply.
4. Save review, then advance/present if appropriate through existing ordered local operations with --defer-sync. Keep the dependent calls sequential; stop on failure rather than advancing unsaved work. Do not auto-grade or skip instruction for speed.
5. When a boundary backup is due, deliver the actual result, reason and full actionable next prompt in commentary BEFORE the backup tool call. Use the learner projection unchanged and include needed explanation. This substantive delivery is the trial endpoint, not an acknowledgement. Finish with brief verified backup status; do not repeat the entire exercise. If no boundary backup is due, deliver the useful response in final.
6. Run one existing hourly_sync milestone at stage boundary, pause or completion. A local save is not synced. On failure, retain state, report the specific failure and retry later without regrading. Preserve existing power-management instructions; no new automation/model change.
7. Save a compact trial observation together with the same lesson milestone, after useful delivery where possible. Do not introduce per-answer network checks or KPI scripts.
